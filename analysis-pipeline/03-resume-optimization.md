# 재개(Resume)와 비용 최적화

파이프라인의 실행 효율을 높이는 설계 원칙입니다.

---

## 점진적 재개 (Incremental Resume)

파이프라인이 중간에 실패하면 처음부터 다시 실행하지 않습니다.
마지막으로 완료된 Stage 이후부터 재개합니다.

### 재개 판정

상태 파일에 기록된 마지막 완료 Stage와 현재 파일 해시를 비교하여 재개 지점을 결정합니다.

### 보존 규칙

| 항목 | 재개 시 | 이유 |
|------|--------|------|
| Layer 1 결과 (파일 목록) | 보존 | 파일 시스템 상태 불변 |
| Layer 2 결과 (번들) | 보존 | 해시 불변이면 번들도 동일 |
| Stage 1 결과 (observation) | 파일 단위로 보존 | 완료된 파일의 observation은 캐시 유효 |
| Stage 2 결과 (Writer/Judge) | 재실행 | 부분 완료 상태를 신뢰할 수 없음 |

---

## Drift 감지

기존 분석 결과가 현재 코드와 얼마나 다른지(drift) 감지합니다.
전체 재분석 대신 변경된 파일만 선별하여 비용을 절감합니다.

### 해시 기반 변경 감지

저장된 파일 해시와 현재 해시를 비교하여 변경/신규/삭제/무변경을 구분합니다.

| 유형 | 감지 방법 | 처리 |
|------|----------|------|
| 변경된 파일 | 해시 불일치 | Stage 1 재분석 + Stage 2 재합성 |
| 신규 파일 | 해시 기록에 없음 | Stage 1 분석 + Stage 2 재합성 |
| 삭제된 파일 | 파일 부재 + 해시 기록 존재 | 해시에서 제거 + Stage 2 재합성 |
| 무변경 파일 | 해시 일치 | 건너뜀 (캐시된 observation 사용) |

---

## Observation 캐시

Stage 1의 파일별 observation 결과를 캐시하여 재사용합니다.

### 핵심 규칙

- 캐시 키는 파일의 `content_hash`입니다
- 파일 내용이 변하지 않으면 observation을 재활용합니다
- 캐시 단위는 파일입니다 (분석 단위 전체가 아님)
- Stage 1 캐시만 재사용 가능합니다. Stage 2는 반드시 재실행합니다 (입력이 달라지므로)

### 무효화 조건

| 조건 | 동작 |
|------|------|
| `content_hash` 불일치 | 캐시 무효, 재분석 |
| 캐시 파일 부재 | 신규 분석 |
| 캐시 파일 손상 | 폐기 후 재분석 |
| 분석 설정 변경 | 전체 캐시 무효화 |

## 지식 축적 (Knowledge Accumulation)

개별 분석의 결과를 프로젝트 수준의 지식으로 축적합니다.
축적된 지식은 이후 분석에서 참조 맥락으로 활용됩니다.

### 핵심 원칙

- 매 분석이 프로젝트 지식을 개선하고, 축적된 지식이 다음 분석의 품질을 높입니다.
- Stage 2/3에서 참조할 때 우선순위를 따릅니다.
- 참조 토큰 상한을 초과하면 우선순위 낮은 것부터 제거합니다.

### 축적되는 지식 유형

| 유형 | 활용 |
|------|------|
| 데이터 모델 맵 | 교차 서비스 의존성 파악 |
| API 엔드포인트 카탈로그 | 호출 체인 추적 |
| 외부 연동 현황 | 장애 영향 범위 예측 |
| 관찰된 패턴 | 프로젝트 전체 경향 파악 |

---

## 원자적 상태 관리

### 불변식

- 상태 파일 갱신 시 중간 상태가 노출되지 않아야 합니다.
- 여러 분석이 동시에 실행될 때 같은 파일에 동시 쓰기를 방지해야 합니다.

### 원칙

- **원자적 쓰기**: 임시 파일에 쓴 뒤 원자적 rename으로 교체합니다
- **경로별 잠금**: 분석 단위별 독립 잠금을 사용하며, 서로 다른 단위는 병렬 가능합니다
- **무결성 검증**: 쓰기 후 파싱 가능 여부를 확인합니다

## 비용 절감 비교

재개 및 캐시 전략 적용 시 비용 절감 효과입니다.

| 시나리오 | 재개/캐시 미적용 | 재개/캐시 적용 | 절감률 |
|---------|--------------|-------------|-------|
| 실패 후 재실행 | 전체 Layer 1-4 재실행 | 완료 Stage 이후부터 재개 | 40~70% |
| 파일 1개 변경 (100파일 프로젝트) | 전체 Stage 1 재실행 | 변경 파일 1개만 Stage 1 재분석 | ~99% |
| 파일 10개 변경 (100파일 프로젝트) | 전체 Stage 1 재실행 | 변경 파일 10개만 Stage 1 재분석 | ~90% |
| 설정 변경 없이 재분석 | 전체 재실행 | 해시 일치 파일 전부 캐시 히트 | 50~95% |
