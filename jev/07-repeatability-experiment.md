# Jev 100개 사례의 10회 반복 실험

> 실행: 2026-09-22 16:55:57–17:10:07 KST · `jev-1.13.0` 직접 HTTP 호출 · 정상 응답 1,000회 · 총 시도 1,001회

## 1. 결론

동일한 입력에서도 확률·점수·confidence는 달라졌지만, 최종 분류는 대부분 유지됐습니다. 최초 3회 실행에서 100개 중 95개의 판단값이 달라져 모든 입력을 총 10회씩 실행했습니다. 최종적으로 **96개에서 숫자 판단값이 변했고, 분류가 변한 것은 1개**였습니다.

다만 일관성이 정확성을 뜻하지는 않습니다. 인용된 환불 문구를 실제 요청으로 잘못 판단하거나, 작성자가 중립으로 분류한 문장을 불만으로 판단하는 결과가 10회 내내 반복됐습니다. 같은 답이 나온다는 이유만으로 자동 처리의 근거로 삼을 수는 없습니다.

## 2. 실험 방법

기존 [Playground 14회 실험](06-playground-experiment.md)과 별도로 합성 고객 문의 100개를 작성했습니다. 환불·배송·계정·기타·정보 부족을 각각 20개씩 구성했으며, 한국어 80개와 영어 20개입니다. 부정·인용문·오늘이 아닌 빠른 처리 요청 등을 포함했고, 기대값은 실행 전에 고정했습니다.

각 입력에 의도 선택(Choice), 명시적인 오늘 마감 여부(Noul), 불만 수준(Score)을 질문했습니다. 질문은 영어 입력에도 한국어 그대로 사용했으며, 모델 버전·문장·질문·요청 본문을 반복 중 바꾸지 않았습니다. 입력과 요청 본문의 해시도 확인했습니다.

100개를 순서대로 한 번씩 호출하는 라운드를 반복했습니다. 요청은 직렬로 실행하고 응답 후 최소 250ms 간격을 뒀습니다. 최초 3회에서 변동이 확인되어 모든 입력을 7회 더 실행했습니다. 도중 HTTP 529 오류 1회로 중단했으나 기존 기록과 입력을 보존해 수동 재개했고, 최종적으로 1,000개 정상 응답을 확보했습니다. 실패한 시도는 결과 비교에서 제외했습니다.

비교는 다음 두 기준으로 나눴습니다.

- 숫자까지 동일: 모델·타입·선택·확률·점수·confidence·legend를 비교하되, 시간·사용량·요청 ID·JSON 키 순서는 제외했습니다. 추가 반올림이나 허용 오차는 적용하지 않았습니다.
- 분류 동일: 의도 선택, Noul의 참·거짓, Score의 최빈 수준을 비교했습니다. Noul은 0.5 초과를 참, 미만을 거짓, 같으면 보류로 처리하고, Score는 최대 확률 수준을 선택하되 동률은 보류했습니다. 운영용으로 검증한 임계값은 아닙니다.

## 3. 핵심 결과

| 지표 | 최초 3회 | 전체 10회 |
| --- | --- | --- |
| 숫자 판단값이 달라진 입력 | 95/100 | 96/100 |
| 최종 분류가 달라진 입력 | 1/100 | 1/100 |
| 의도 선택이 달라진 입력 | 0/100 | 0/100 |
| 오늘 마감 분류가 달라진 입력 | 0/100 | 0/100 |
| 불만 최빈 수준이 달라진 입력 | 1/100 | 1/100 |

전체 10회에서 숫자까지 같았던 입력은 4개, 세 분류가 모두 유지된 입력은 99개였습니다. 숫자가 달라진 96개 중 95개는 분류가 유지됐습니다. 동일 입력의 실행 쌍 4,500개를 비교하면 숫자까지의 일치는 10.20%, 세 분류의 일치는 99.80%입니다. 이는 반복 일치율이지 정답률이 아닙니다.

작성자 기대값과 세 분류가 모두 일치한 비율은 첫 실행 기준 97/100, 전체 반복 관측 기준 979/1,000이었습니다. 입력별 10회 최빈 분류를 사용하면 98/100이지만, 이는 사후 분석이며 반복 호출을 운영 전략으로 채택한 것은 아닙니다. 반복 1,000회를 독립된 문장 1,000개로 해석해서도 안 됩니다.

## 4. 결과의 의미

### 숫자 변동과 업무 판단 변동은 구분해야 함

확률이나 confidence의 변화가 항상 처리 결과의 변화를 뜻하지는 않았습니다. 반면 불만 수준의 확률이 비슷하게 나뉜 입력에서는 작은 차이가 최빈 수준을 바꿨습니다. 그 입력의 Score confidence는 10회 모두 0이었습니다.

Score 평균을 반올림한 값이 최빈 수준과 다른 경우도 확인했습니다. 평균·최빈 수준·confidence는 서로 다른 정보를 담으므로 대신 사용하면 안 됩니다. 변동의 내부 원인이 샘플링·병렬 계산·서비스 부하 중 무엇인지는 확인하지 못했습니다.

### 반복되는 오분류도 별도로 검토해야 함

인용문을 제외하라는 지시가 있어도 인용된 환불 표현을 실제 의도로 선택한 결과가 10회 반복됐습니다. 빠른 처리를 요구하지만 명시적 불만은 없는 문장도 작성자 기준과 달리 불만으로 분류됐습니다. 인용문과 실제 요청의 구분, 중립과 불만의 경계는 별도 검토가 필요합니다.

기존 [설명용 정책](06-playground-experiment.md#7-설명용-처리-흐름)을 당시 저장한 응답에 적용했을 때 처리 경로가 바뀐 입력은 없었습니다. 그러나 잘못된 환불 검토 경로 역시 10회 유지됐습니다. 보류 정책이 변동을 흡수하는 것과 오류를 막는 것은 다릅니다. 실제 환불이나 업무 실행은 하지 않았으며, 이 결과로 기존 confidence 0.5 기준을 운영 기준으로 확정하지 않았습니다.

### 반환 수치의 정밀도에도 한계가 있음

직접 HTTP 응답에서도 확률·점수·confidence의 숫자 12,000개는 모두 0.01 단위였습니다. Score와 반환 확률의 가중합은 304회에서 최대 약 0.01 차이가 났고, 일부 확률 분포의 합은 0.99였습니다. 따라서 Playground 화면 표시만의 문제로 설명할 수는 없습니다.

반올림과 양립하는 차이지만 내부 정밀도나 계산 과정을 확인하지 못했으므로 계산 버그라고 단정하지 않습니다. 당시 분석에서는 반환값을 임의 보정하지 않았습니다.

## 5. 시간·사용량·비용

정상 응답의 클라이언트 경과 시간은 중앙값 238.15ms, p95 325.64ms였으며 최소 177.97ms, 최대 569.62ms였습니다. 요청 시작부터 응답 읽기·파싱·검증까지 측정한 값으로, 요청 사이 대기와 약 5분 45초의 중단 시간은 제외했습니다. 서비스 내부 평가 시간이나 동시 부하 성능을 측정한 것은 아닙니다.

정상 응답에서 합산한 사용량은 입력 702,710토큰, 출력 86,190토큰입니다. 실험일 확인한 공개 단가인 입력 100만 토큰당 $0.042와 출력 무료 조건을 적용하면 참고 비용은 약 **$0.0295**입니다. 실제 청구액·실패 요청 비용·크레딧·할인은 확인하지 않았습니다. [당시 참고한 Models 가격](https://docs.typesafe.ai/models)

## 6. 한계와 근거 자료

이번 결과는 작성자가 구성한 합성 입력 100개의 단일 세션 관측입니다. 실제 고객 요청의 무작위 표본이나 독립된 사람 검수 정답셋이 아니므로, 일반 정확도·한국어 전체 품질·확률 보정·운영 SLA·보안 성질을 입증하지 않습니다. 실제 도입 판단에는 업무 담당자의 라벨 검토, 자연스러운 긴 문맥, 다른 시점·부하·모델과의 비교가 별도로 필요합니다.

실험 당시 1,000개 정상 결과와 입력별 10회 실행, 중복 없음, 요청 본문 해시를 검증했습니다. 이후 문서 중심으로 정리하면서 실험용 코드·테스트·입력 스냅샷·원시 응답·실패 및 재개 기록·분석 JSON은 저장소에서 제거했습니다. 이 문서는 당시 관측과 집계 결과를 정리한 보고서이며, 현재 저장소만으로 원문 대조나 재집계는 할 수 없습니다.

실험 전용 API 키는 종료 후 비활성화했습니다. 키 원문은 저장소에 기록하지 않았으며, 콘솔의 비활성 메타데이터는 남아 있습니다.
