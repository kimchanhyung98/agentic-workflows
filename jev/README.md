# Jev 리서치

TypeSafe의 Jev를 자동화의 목표, 판단 API의 계약, 유사 프로젝트와의 차이, 도입 평가 관점에서 분석합니다.

> 상태: 공개 자료 조사 + Playground 14회 + 직접 HTTP 정상 결과 1,000회 · 확인일: 2026-09-22 · SDK·운영 평가는 미수행

## 한눈에 보기

Jev는 주어진 문맥과 질문을 받아 선택·점수·참일 확률을 반환하는 모델입니다. 자유로운 문장 생성 대신 제한된 결과를 코드에서 사용하도록 설계됐습니다. 다만 출력 형식의 보장과 판단의 정확성은 다릅니다. [공식 소개](https://docs.typesafe.ai/introduction)

이 리서치의 결론은 다음 세 가지입니다.

1. Jev는 전체 업무를 수행하는 에이전트가 아니라, 코드에서 호출하는 좁은 의미 판단의 후보입니다.
2. 형식이 유효한 결과, 잘 보정된 확률, 올바른 업무 완료는 서로 다른 검증 대상입니다.
3. 도입 여부는 홍보 배수보다 같은 업무의 오류율·보류 비중·전체 비용을 비교해 판단해야 합니다.

## 실제 실행에서 확인한 점

100개 사례를 각각 3회 실행했을 때 95개에서 판단값이 달라져 전체를 총 10회씩 실행했습니다. 최종적으로 96개에서 숫자가 달랐지만 분류 변경은 1개였으며, 같은 오분류를 10회 반복한 사례도 있었습니다. 정상 결과는 1,000개이고 529 오류 1회로 실제 시도는 1,001회입니다. 실험 방법·주요 결과·해석과 한계는 [반복 실험 보고서](07-repeatability-experiment.md)에 있습니다.

## 적용 판단

다음은 현재 자료를 바탕으로 한 선택 가이드이며 성능 순위나 도입 확정이 아닙니다.

| 작업·조건 | 우선 검토할 방식 |
| --- | --- |
| 규칙으로 표현하기 어려운 의도·관련성·위험 수준 판단 | Jev와 업무별 분류 모델을 같은 정답셋으로 비교 |
| 합계·날짜·권한·중복 처리 조건 | 코드와 업무 시스템의 확정적 규칙 |
| 설명문·코드·새로운 내용 생성 | 생성 모델, 필요하면 구조화 출력 결합 |
| 알려진 경로 중 의미상 가까운 경로 선택 | 임베딩 라우터와 판단 모델 비교 |
| 한국어·민감한 실행·낮은 오류 허용도 | 별도 평가, 보류·사람 승인 정책을 먼저 정의 |

## 근거의 범위

외부 출처는 TypeSafe와 비교 대상 프로젝트의 공식 문서, 직접 확인한 TypeSafe 콘솔로 제한합니다. 공식 문서의 설명·공급자 평가와 자체 관측을 구분합니다. Playground 실험은 콘솔의 화면 JSON을, 100개 반복 실험은 직접 HTTP 응답 원문을 분석했습니다. 직접 HTTP 실험을 콘솔에서 실행한 것으로 표현하지 않습니다. 일반 정확도·확률 보정·운영 지연 보장·실제 청구액·업무 완료는 검증하지 않았으며, 가격·버전·제한은 확인일 이후 바뀔 수 있습니다.

현재 저장소에는 조사·실험 보고서만 유지합니다. 실험용 코드·테스트·입력 파일·원시 응답은 제거했으므로 문서의 집계는 당시 분석 결과이며, 저장소만으로 재집계할 수 없습니다.

공식 문서와 직접 실행 보고서는 [자료 색인](05-references.md)에 정리했습니다. 이 디렉토리의 문서는 다른 리서치 디렉토리 없이 읽을 수 있습니다.
